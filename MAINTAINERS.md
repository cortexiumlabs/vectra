# Maintainers – Synentra

This document lists the current Maintainers of the Synentra project and describes their 
responsibilities, expectations, and lifecycle within the project governance model.

Maintainers are responsible for the technical direction, health, and governance of the 
Synentra project. They act as individuals participating in an open-source community, 
not as representatives of their employers.

## Maintainer Responsibilities

Maintainers are responsible for the overall stewardship of the project, including:

* Defining and evolving the project’s technical direction
* Reviewing and approving significant pull requests
* Participating in architectural and design decisions
* Managing release planning and execution
* Coordinating security response and disclosures
* Ensuring project health, sustainability, and quality
* Upholding the Code of Conduct
* Supporting and mentoring Contributors and Committers

## Organizational Neutrality

Maintainers act as individuals and not as representatives of their employers.

No single organization should dominate the Maintainer group. The project aims to maintain diversity across organizations to ensure healthy governance and reduce single-vendor risk.

## Transparency

Maintainer decisions are made in public wherever possible, including:

* GitHub issues and pull requests
* Design documents
* Public discussions
* Community meetings

All governance-related decisions must be recorded in a publicly accessible location.

## Changes to This Document

Changes to this document must follow the governance process defined in [`GOVERNANCE.md`](GOVERNANCE.md), including:

* Public discussion
* Formal proposal via pull request
* Approval by a two-thirds (2/3) supermajority of active Maintainers
